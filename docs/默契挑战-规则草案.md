# 默契挑战 · 规则

> 状态:**已实现**(2026-11-01)。五个待定项和收场方式已于 2026-11-01 确认,实现见 `server.js` 的默契挑战部分与 `public/app.js` 的 match 视图。
> 本文档保留为设计记录;实际行为以代码和「已确认的规则」一节为准。

## 背景

在现有「传声筒」项目里增加第二款小游戏:2–4 人的默契挑战。玩家同时输入词汇,提交前互不可见;词语不一致,就基于上一轮的词继续联想,直到全员在同一轮说出同一个词。

## 一句话规则

2–4 人同时作答、互相看不到;每轮 40 秒,根据上一轮大家说出的词继续联想,直到**所有人在同一轮说出完全相同的词**,就算成功相遇。

## 一局流程

1. 开局时,如果房主开着**「指定主题」**(默认),系统给出一个起始主题(如「夏天」「旅行」「红色」);关掉则自由起手。本局不会换主题。
2. **第一轮**:所有人凭第一直觉输入一个词。提交前看不到任何人的答案。
3. 全部在线玩家提交或 40 秒到 → 同时揭晓本轮所有人的词。
4. 判定:
   - 所有参与本轮的人(2–4 人)的词完全一致 → 成功相遇,本局结束。
   - 有人不同 → 进入下一轮。
5. **下一轮**:大家看到上一轮所有人的词,各自输入一个「能把大家拉近」的新词。提交前仍然看不到本轮别人的答案。
6. 重复,直到全员同词;本局不设轮数上限,房主可以随时结束。

## 规则细节

- **提交即锁定**,不能修改。
- **全部提交立即揭晓**,不用等满 40 秒。
- **每轮 40 秒**,从上一轮揭晓后开始倒计时;揭晓页停留 8 秒自动进入下一轮。
- **指定主题**:大厅开关,默认开启。关闭后不显示主题,第一轮完全自由起手。
- **判同只认完全相同的词**:忽略空格、标点、大小写;同义词、近义词、谐音都不算,否则程序无法可靠判定。
- **词语长度**:1–8 个字,一个词或短词组。
- **必须输入新词**:不能重复自己上一轮的词,避免原地打转;是否与上一轮有语义关联靠自觉。超时自动沿用的词不受此限制。
- **禁止交流**:提交前不能讨论、不能暗示,包括语音和表情。
- **超时**:自动沿用自己的上一轮的词;第一轮没有旧词,记为「未答」。
- **轮数上限**:不限。房主在游戏中可随时点「结束本局」,按已揭晓的轮数结算;当前还没揭晓的那一轮不计入。
- **掉线**:本轮弃权,不参与判同;如果揭晓时在线人数不足 2 人,本局结束。
- **中途重连**:回到牌桌后,从下一轮开始重新参与;如果本轮还没揭晓,可以直接交卷。

## 3–4 人怎么算成功

已确认:**全员同词**。所有参与本轮的玩家在同一轮说出同一个词,才算团队相遇。

| 方案 | 规则 | 特点 |
|---|---|---|
| 全员同词(已采用) | 所有人同一轮同词 | 团队默契,最符合「组队」 |
| 两两配对 | 4 人分 2 队,队内 2 人同词即成功 | 更快、可对抗(未实现) |
| 任意两人同词 | 任意两人同词就成功 | 太容易(未采用) |

## 结算与评级

按用了几轮相遇:

| 轮数 | 称号 |
|---|---|
| 1 轮 | 心有灵犀 |
| 2 轮 | 默契十足 |
| 3–4 轮 | 脑回路接近 |
| 5 轮以上 | 终于走到一起 |
| 房主结束 / 人不够 | 各想各的 |

结算页展示**每一轮的词**,形成一条「思维轨迹」,这通常是最好笑的部分。

已确认按**单题结算**:一局结束后直接显示轮数、称号和轨迹,想再玩就点「再来一局」回到大厅。不做连续多题累计分。

## 两个示例

**2 人,主题「夏天」**

```
第 1 轮:阿甲「西瓜」   阿乙「空调」
第 2 轮:阿甲「凉快」   阿乙「冰」
第 3 轮:阿甲「冰」     阿乙「冰」     → 相遇
```

**3 人,主题「旅行」**

```
第 1 轮:甲「海边」 乙「飞机」 丙「行李箱」
第 2 轮:甲「度假」 乙「出发」 丙「行李」
第 3 轮:甲「出发」 乙「出发」 丙「度假」
第 4 轮:甲「海边」 乙「海边」 丙「海边」 → 相遇
```

## 灵感与可选变体

> 以下都是备选方向,当前版本均未实现。

- **主题起手**:系统给主题,第一轮写第一反应,比纯自由起手更容易相遇。
- **自由起手**:不给主题,纯凭直觉,难度和惊喜都更高。
- **桥梁词**:每轮必须造一个能同时关联上一轮所有词的词。
- **禁止重复**:整局不能出现之前任何轮次说过的词。
- **2v2 对抗**:4 人分两队,队内先同词者获胜。
- **连续挑战**:一局 3 题,累计默契分和称号。
- **关键词轮**:某一轮必须用动词、颜色、食物等指定类型(类似传声筒的限制卡)。
- **最后 10 秒才显示倒计时**:制造紧张感。
- **轨迹回放**:结束后逐轮展示,突出「你们是怎么越走越近的」。
- **默契徽章**:根据轮数和人数发不同称号,可跨局累计。

## 和现有系统的整合

- 新增一级「小游戏桌」页面:先选传声筒或默契挑战,再起名字入座。房间空着时,第一位入座的人决定本房间的游戏;房间已有人时只能加入当前游戏。
- 入座后房主仍可在大厅切换游戏。
- 默契挑战人数 **2–4**,传声筒保持 3–8;切换游戏后大厅只显示对应的开关。
- 默契挑战大厅提供「指定主题」开关,默认开启;关闭后自由起手。卧底、限制卡、类别词库和历史记录在大厅里隐藏。
- 复用现有的房主权限、SSE 实时同步、在线检测、掉线宽限和计时机制。断线宽限默认 5 分钟,重连时页面提示并恢复身份;房主可以手动移出离线玩家。
- 结果页不需要「最猪」和「猜卧底」投票,直接显示相遇轮数、称号和每轮轨迹。

## 已确认的规则(2026-11-01)

1. **3–4 人成功条件**:全员同词。
2. **第一轮起手**:默认系统给主题;大厅提供「指定主题」开关,关闭后自由起手。
3. **轮数上限**:不限轮数;房主可随时结束本局,当前未揭晓的一轮不计入。
4. **超时**:沿用自己上一轮的词;第一轮没有旧词,记为「未答」。
5. **题目数量**:单题结算,不做连续多题累计分。

## 实现备忘

- 服务端用 `game.mode` 区分 `chain`(传声筒)和 `match`(默契挑战);`game.match` 保存 `theme`、`round`、`stage`(input / reveal / result)、`submissions`、`sources`、`history` 和 `result`。
- 空房间的第一次 `POST /api/join` 带 `mode` 决定房间游戏;房间已有人时模式不一致返回 409。入座后房主可用 `POST /api/mode` 切换。
- `game.options.theme` 控制开局是否指定主题;关闭时 `game.match.theme = ''`,前端显示「自由起手」。
- `phase` 增加 `match`(输入或揭晓)和 `matchresult`(结算);`game.match.stage` 区分输入与揭晓。
- 计时:默契挑战默认每轮 40 秒(`MATCH_SECONDS`),揭晓停留 8 秒(`MATCH_REVEAL_SECONDS`);传声筒仍是 45 秒(`TURN_SECONDS`)。
- 人数:join 和 start 都按模式校验,默契 2–4 人,传声筒 3–8 人;大厅切到默契挑战前如果已超过 4 人会被拒绝。
- 判同复用 `rules.js` 的 `normalize()`,只做完全相等比较。
- `viewFor` 在输入阶段只返回本人的词和别人的「已提交」状态;完整词只在揭晓 / 结果阶段通过 `history` 返回。
- 在线玩家全部交卷立即揭晓;超时由服务端收卷。离线且没交卷的人本轮弃权,不参与判同;在线少于 2 人时本局结束。
- 前端复用 SSE、倒计时、在线标签、房主权限;新增一级选游戏界面、大厅模式切换和主题开关、输入 / 等待 / 揭晓 / 结算视图。提交状态用轻量 DOM 更新,避免玩家输入时整页重建。
- 已实现,所以本节不再是待办清单。
